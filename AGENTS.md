# AGENTS.md — Архитектурный эталон (Nexus English App)

Этот проект — приложение для изучения английского языка на **Flutter**. Поскольку проект находится на ранней стадии (`lib/main.dart`), любой новый код должен с самого начала выстраиваться по единому эталону **Clean Architecture (Feature-first)**, принятому в наших языковых приложениях.

## 1. Целевой технологический стек
При добавлении зависимостей в `pubspec.yaml` ориентируйся на проверенный стек:
- **UI и фреймворк:** Flutter (Material Design), строгий LTR (`TextDirection.ltr`).
- **Стейт-менеджмент:** `flutter_bloc` + `equatable`.
- **Локальная БД:** `drift` + `drift_flutter` (dev: `build_runner`, `drift_dev`).
- **Сеть и хранение:** `dio`, `flutter_secure_storage`.
- **Аудио и речь:** `just_audio`, `flutter_tts`.
- **Тестирование:** `flutter_test`, `bloc_test`, `mocktail`.

## 2. Целевая структура папок (`lib/`)
Создавай модули строго по этой иерархии:
- `lib/core/` — базовый слой приложения:
  - `audio/` — гибридный сервис озвучки (локальные ассеты + fallback на TTS с локалями `en-US` / `en-GB`).
  - `database/` — локальная база данных `AppDatabase` (Drift).
  - `error/` — базовые классы `Failure`.
  - `logging/` — логгер приложения.
  - `network/` — фабрика `Dio` и чтение JSON.
  - `result/` — монадный тип `Result<T>` (`Success` / `Error`).
  - `settings/` — хранение пользовательских настроек (выбор акцента US/UK, уровень языка, цели).
  - `speech/` — распознавание речи и оценка произношения.
  - `widgets/` — общие UI-компоненты.
- `lib/features/<feature>/` — фичи (`home`, `dictionary`, `grammar`, `listening`, `srs`, `stories`, `slang`, `speech_lab`, `progress`):
  - `data/` — модели, парсеры JSON-сидов (`assets/seed/`), реализации репозиториев.
  - `domain/` — чистые Dart-сущности и контракты репозиториев.
  - `presentation/` — BLoC (`*_bloc.dart`, `*_event.dart`, `*_state.dart`), страницы и виджеты.

## 3. Стандарты разработки с первого дня
1. **Изоляция слоёв:** Никакой бизнес-логики и прямых вызовов БД/API в `main.dart` и виджетах. Вся работа с данными — через репозитории и BLoC.
2. **Безопасность данных:** Все репозитории возвращают `Result<T>`. Операции ввода-вывода оборачиваются в `try-catch` на уровне `data/`.
3. **Английская специфика:** При проверке ответов пользователя в упражнениях и SRS учитывай сокращения (`don't` / `do not`, `I'm` / `I am`), регистр и пунктуацию, чтобы не засчитывать верный ответ как ошибку из-за апострофа.
4. **Иммутабельность и Equatable:** Все события и состояния BLoC наследуются от `Equatable` и имеют `const` конструкторы.
5. **Чистота кода:** После каждого этапа разработки запускай `flutter analyze` и покрывай ключевую логику BLoC тестами на `bloc_test` + `mocktail`.
